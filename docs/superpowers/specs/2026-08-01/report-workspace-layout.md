# 报告工作台页面视觉优化

## 目标

重新整理“分析诊断报告”“导入诊断报告”“比较诊断报告”及共用历史记录选择窗口，使页面在尚未选择报告时也具有完整、平衡的布局，并与已确认的方案 A 视觉体系保持一致。

本次只调整 Android 页面结构、样式和展示文案，不修改报告读取、历史记录查询、分析、比较、导入或诊断逻辑。

## 设计依据

采用 Android 官方设计建议中的以下原则：

- 使用明确的内容容器对相关信息进行分组；
- 紧凑型手机页面保持统一的 16dp 左右边距；
- 空状态应解释当前状态，并提供清晰的下一步操作；
- 滚动页面应填满可用视口，背景和安全区不能在内容较少时中断；
- 历史记录属于列表—详情场景，列表项应具有可快速识别的信息层级，而不是把全部信息压在一行。

参考资料：

- <https://developer.android.com/design/ui/mobile/guides/layout-and-content/content-structure>
- <https://developer.android.com/design/ui/mobile/guides/layout-and-content/common-layouts>
- <https://developer.android.com/design/ui/mobile/guides/layout-and-content/adapt-layout>

## 整体视觉方向

沿用方案 A 的蓝灰页面背景、白色内容卡片、细灰描边、深色正文和克制的蓝色强调色。

- 页面背景必须从状态栏安全区连续覆盖到导航栏安全区；
- 白色卡片用于承载一组完整任务或报告结果；
- 数据来源按钮保持同级白底描边样式，不默认突出其中一个来源；
- 蓝色只用于状态标识、图表和真正的主要结果，不用于把普通文件入口误表现为主要操作；
- 空状态通过居中的任务卡片平衡纵向空间，不使用无意义的大图或装饰；
- 页面出现足够内容后自然滚动，不能依靠固定屏幕高度裁切内容。

## 分析诊断报告

### 尚未选择报告

标题和页面说明下方显示一张“分析工作台”空状态卡片。卡片在可用内容区内保持视觉居中，但在小屏或横屏时仍可随页面滚动。

卡片内容顺序：

1. 小型分析图形标识；
2. 标题“选择一份诊断报告”；
3. 说明“选择后将生成关键指标、信号趋势、应用流量构成和文字分析”；
4. `ZIP`、`JSON` 两个支持格式标记；
5. “从历史记录选择”和“从本地文件选择（最近 / 浏览）”两个同级白底描边按钮。

两个按钮保持相同视觉权重，不暗示历史记录或本地文件是默认来源。

### 正在读取

选择报告后，空状态卡片切换为读取状态卡片。读取状态保留明确的任务标题和进度文字，不只在页面左上角显示孤立的一行文字。

### 分析结果

读取完成后按以下顺序展示：

1. 报告摘要卡片：报告名、设备、模式；
2. 关键指标区域：系统移动流量、隧道观察流量、平均下载和平均信号，使用两列指标网格；
3. 信号趋势卡片；
4. 应用流量构成卡片；
5. 文字分析卡片。

分析结果继续使用现有数据和计算，不增加新的诊断结论。

## 导入诊断报告

### 尚未选择文件

标题和说明下方显示一张居中的“本地报告导入”任务卡片，包含：

1. 文件/报告标识；
2. 标题“选择手机中的诊断报告”；
3. ZIP、JSON 支持格式标记；
4. 只读导入、不覆盖历史诊断的说明；
5. “选择本地报告”白底描边按钮。

该按钮必须使用与比较、分析页面数据来源按钮相同的 `NEUTRAL` 视觉角色，移除当前淡蓝色背景。

### 导入结果

读取成功后，空状态卡片替换为完整的报告摘要卡片，显示名称、设备、状态、快照和系统移动流量。卡片下方保留清晰的后续提示，说明可回到分析或比较页面继续使用该报告。

读取失败时在同一内容区显示错误状态，同时保留重新选择文件的入口。

## 比较诊断报告

用户描述的“报告 A 和报告 B 背景淡蓝、下方纯白”按比较诊断报告页面处理。

- 页面蓝灰背景完整覆盖视口，不在报告 B 下方切换为白色；
- 报告 A、报告 B 和比较结果均使用同一套白色卡片；
- 两张来源卡片保持相同尺寸、间距和按钮样式；
- 已选择状态显示报告文件名和设备信息，未选择状态显示简洁占位文案；
- 不改变 A、B 报告的选择、保存状态和比较计算逻辑。

## 历史记录选择窗口

现有固定约 40dp 高度的紧凑文字行改为宽松的报告卡片行。

每条记录包含：

1. 第一行：报告文件名，最多两行，超长时省略；
2. 第二行：诊断开始时间；
3. 第三行：严格/标准模式与已完成/已中断状态；
4. 右侧进入指示符。

列表项要求：

- 最小高度 76dp；
- 卡片之间保留 8dp 间距；
- 卡片内边距至少 12dp；
- 默认白色背景、细灰描边；
- 点击整张卡片即选择并关闭窗口；
- 弹窗具有合理最大高度，记录较多时只滚动列表；
- 不引入额外确认步骤，不改变选择后的回调。

## 响应式与安全区

- 报告页面的 `ScrollView` 使用填充视口行为，使内容较少时页面仍覆盖整个可用高度；
- 空状态内容区使用剩余空间进行垂直平衡，不写死 K60/K80 像素坐标；
- 内容增加后允许自然滚动；
- 继续使用现有 `WindowInsets` 逻辑避开状态栏和三键/手势导航栏；
- K60、K80 使用同一套布局实现。

## 测试与验收

自动化验证：

- 分析页面初始状态存在完整工作台卡片和两个同级数据来源按钮；
- 导入页面按钮为 `NEUTRAL`，并存在完整空状态卡片；
- 报告页面 `ScrollView` 启用填充视口；
- 比较页面 A、B 卡片和页面背景使用统一表面体系；
- 历史选择列表项高度、信息层级、间距和点击回调符合规格；
- 原有导入、分析、比较和历史记录测试继续通过；
- 全量单元测试、Lint 和 Debug APK 构建通过。

真机验证：

- 在当前连接的 Redmi 真机分别截取分析空状态、导入空状态、比较页面和历史选择窗口；
- 确认页面背景覆盖到底部导航安全区；
- 确认中下方空间得到合理利用，没有新的拥挤或遮挡；
- 确认四个页面不与系统状态栏、导航栏重叠；
- 覆盖安装前后不得改变或删除现有诊断记录。
