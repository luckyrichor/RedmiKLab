# 物理蜂窝测速候选加固规格

## 目标

主动测速只允许绑定真正的物理移动数据网络。带 VPN 标记的网络、IMS/EIMS 等运营商专用网络不得成为测速候选；无法安全确认物理网络时，本轮测速明确失败并保留诊断证据。

本次加固同时支持 Redmi K60 与 K80，不按机型分叉，不改变测速端点、主备重试次数、重试间隔、单次流量上限或每晚预算。

## 已确认的真机证据

K80 当前网络同时出现：

- `218`：电信 5G 物理数据网络，`CELLULAR`，接口 `rmnet_data1`；
- `219`：IMS 专用网络，`CELLULAR + IMS`，没有 `INTERNET`；
- `221`：RedmiKLab 本地 VPN，`CELLULAR + VPN`，接口 `tun0`，系统内部底层网络为 `218`。

现有策略给 `218` 与 `221` 相同高分，也给 `219` 一个低优先级回退分。当前测试因为网络遍历顺序而正确选中 `218`，但不能依赖该顺序。

## 方案比较

采用“VPN 会话记录底层网络 + 能力白名单”方案。它能在正常网络和 HyperOS 缺失 `INTERNET` 标记两种情况下确认同一个物理网络，且不依赖遍历顺序。

未采用的方案包括：

- 只排除 VPN/IMS：改动较小，但在多卡或多个普通蜂窝候选同时存在时仍无法确认无 `INTERNET` 网络的身份。
- 根据 `rmnet`、`tun` 等接口名前缀判断：实现简单，但依赖厂商、系统版本和运营商命名，不符合 K60/K80 统一兼容要求。

## 候选规则

每个网络转换为独立的候选事实，至少包含：

- 是否具有 `CELLULAR` 传输；
- 是否具有 `VPN` 传输；
- 是否具有 `IMS`、`EIMS` 或 `MMS` 专用能力；
- 是否具有 `INTERNET`、`VALIDATED` 与 `NOT_SUSPENDED` 能力；
- 网络 ID 是否等于 RedmiKLab 当前 VPN 会话记录的底层网络 ID。

选择规则按以下顺序执行：

1. 没有 `CELLULAR` 的网络直接拒绝。
2. 带 `VPN` 传输的网络直接拒绝，即使它同时继承了 `CELLULAR`。
3. 带 `IMS`、`EIMS` 或 `MMS` 专用能力的网络直接拒绝。
4. 未验证或已暂停的网络直接拒绝。
5. 具备 `INTERNET` 的安全物理蜂窝网络可以作为正常候选。
6. 缺少 `INTERNET` 的网络只有在以下条件同时成立时才可作为兼容回退：系统默认网络是已验证 VPN，且网络 ID 等于 RedmiKLab 本次 VPN 会话明确记录的底层网络 ID。
7. 正常候选优先于兼容回退；RedmiKLab 明确记录的底层网络在同等级候选中优先。
8. 没有候选时返回明确的“无安全物理蜂窝网络”结果，不绑定 VPN、IMS 或未知网络。

## VPN 会话底层网络记录

Android 公共 SDK 支持 VPN 创建方调用 `VpnService.Builder.setUnderlyingNetworks`，但不向普通 App 提供读取系统内部 VPN 底层网络列表的公共接口。因此由 RedmiKLab 在建立本地 VPN 时完成以下动作：

1. 在隧道建立前，从可见网络中选择具备 `CELLULAR + INTERNET + VALIDATED + NOT_SUSPENDED`，且不带 VPN/IMS/EIMS/MMS 的物理数据网络。
2. 若找到，将其传给 `setUnderlyingNetworks`，并把网络 ID 保存为当前 VPN 会话底层网络 ID。
3. VPN 停止、建立失败或转发器启动失败时清除该 ID。
4. 若启动时没有安全网络，VPN 可以按现有生命周期退出；不得保存推测出来的 ID。
5. 网络 ID 只用于当前 VPN 会话，不跨 VPN 重建永久复用。

对于 Clash 等外部 VPN，RedmiKLab 没有可信的会话底层 ID。具备 `INTERNET` 的安全物理蜂窝网络仍可正常测速；若它缺少 `INTERNET`，则明确失败，不使用接口名或遍历顺序猜测。

## 诊断与报告

现有 `PROBE_NETWORK_DIAGNOSTIC` 继续记录全部可见网络，并新增或明确记录：

- VPN 会话记录的底层网络 ID；
- 网络是否因 VPN 传输被拒绝；
- 网络是否因 IMS/EIMS/MMS 能力被拒绝；
- 网络是否匹配已记录的底层网络；
- 最终选择结果或“无安全物理蜂窝网络”失败原因。

报告不能把“没有安全候选”误写成 DNS、连接或测速端点失败。

## 测试要求

生产代码继续测试先行。至少覆盖：

- `CELLULAR + VPN` 即使具备 `INTERNET` 也被拒绝；
- IMS、EIMS、MMS 网络均被拒绝；
- 正常物理蜂窝网络被选择；
- 已验证 VPN 下，只有匹配会话底层 ID 的无 `INTERNET` 物理网络可回退；
- 未匹配底层 ID、外部 VPN 或没有会话 ID 时拒绝无 `INTERNET` 网络；
- 正常候选优先于兼容回退；
- VPN 启停、建立失败和转发失败正确保存或清除会话底层 ID；
- 诊断 JSON 能区分拒绝原因和最终选择结果。

## 真机验收顺序

1. 完整运行 `test lintDebug assembleDebug`。
2. 确认 K80 没有运行中的诊断后覆盖安装，验证数据库记录保留且 App 不闪退。
3. 开启 RedmiKLab 连接级采集，亮屏触发一次主动测速；必须选择物理蜂窝网络，VPN 与 IMS 的候选分必须为空。
4. 完成亮屏验收后再安排锁屏诊断，分别验证任务唤醒、物理网络选择、测速结果及快照不被重试阻塞。

## 非目标

- 不使用 `rmnet_data1`、`tun0` 等接口名称判断网络身份。
- 不使用 Root、隐藏 API 或反射读取系统内部 VPN 状态。
- 不让 RedmiKLab 连接级采集与 Clash 同时运行。
- 不为无法确认的网络提供“尽量试一下”的不安全回退。
