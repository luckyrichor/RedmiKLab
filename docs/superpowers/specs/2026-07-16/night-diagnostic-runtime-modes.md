# 夜间诊断运行模式与短任务架构

## 目标

修复 Android 15+ 对 `dataSync` 前台服务的六小时累计限制造成的提前中断。提供“标准模式”和“严格模式”，两种模式都不再依赖连续运行数小时的 `dataSync` 服务，并准确记录每次采样的计划时间、实际时间和延迟。

## 模式语义

### 标准模式

- 默认模式。
- 不在整个诊断窗口持续持有 CPU 部分唤醒锁。
- 开始、周期快照、主动测速、结束与恢复事件均以持久化计划为依据。
- 周期任务使用一次性系统调度唤醒短任务；Doze 可能导致执行晚于计划时间。
- 连接级采集已启用时，VPN 继续持续保存实际连接；未启用时仍保留应用流量汇总、信号和主动测速。
- 报告必须显示实际延迟，不能为错过的时刻伪造快照。

### 严格模式

- 用户显式选择，界面名称只写“严格模式”；采样间隔是独立参数。
- 必须已启用连接级采集并获得本地 VPN 授权，否则不得安排严格模式诊断，也不得静默降级。
- 诊断窗口内由连接级 VPN 服务持有 CPU 部分唤醒锁，并用单调时钟按所选间隔触发快照。
- 系统闹钟只负责开始、结束、主动测速、异常恢复和最终结算，不承担高频五分钟唤醒。
- 界面明确提示耗电、发热、建议充电以及与 Clash Meta 等其他 VPN 互斥。
- 严格模式提高准时率，但报告仍按实际时间计算延迟，不宣称系统级绝对实时保证。

## 配置生效规则

- 模式、采样间隔和窗口在诊断真正开始时写入 Run，随后对本次 Run 锁定。
- 计划已安排但尚未开始时，修改模式或间隔会影响下一次即将开始的计划；无需取消并重新安排，因为开始事件读取当时的最新配置。
- 诊断已经运行时修改设置只影响下一次 Run。
- 运行中若需改变本次模式，必须先停止当前诊断，再用新配置启动新 Run。
- 页面必须显示当前设置、已计划状态，以及当前运行中的 Run 实际采用的模式和间隔，避免把“下一次设置”误认为“本次运行状态”。

## 调度职责

- 开始事件：创建唯一 Run、保存配置快照、生成开始快照、启动所需采集器并安排后续事件。
- 周期快照：调用统一快照执行器；标准模式由短任务执行，严格模式由 VPN 采集器内部计时执行。
- 主动测速：按配置间隔启动独立短任务；单轮有总时限，完成或失败后立即停止。
- 结束前检查点：在用户结束时刻前 120 秒生成安全快照并验证 Run 上下文。
- 正式结束：生成最终快照、停止采集、释放唤醒锁、结算 Run。
- 异常恢复：根据数据库里的活动 Run、计划结束时刻和最后成功动作决定恢复、补结算或标记中断，不依赖旧服务实例的内存字段。

## `dataSync` 服务

- `NightDiagnosticService` 改为动作型短服务，不再持有整个窗口生命周期。
- 每次只处理一个开始、快照、测速、结束或恢复动作，数据写入成功后立即停止。
- Android 15+ 实现 `onTimeout(startId, fgsType)`：写入明确原因、保存能够安全保存的状态并在系统宽限期内停止，不能再次触发 `ForegroundServiceDidNotStopInTimeException`。
- 同一动作必须幂等；重复闹钟、服务重启或连续点击不能重复创建 Run、重复最终结算或重复生成同一计划时刻的快照。

## 持久化模型

Run 至少保存：

- 唯一 Run ID；
- 计划开始与计划结束时间；
- 实际开始与实际结束时间；
- `STANDARD` 或 `STRICT` 模式；
- 本次锁定的采样、连通性和吞吐间隔；
- 本次是否启用连接级采集；
- 当前状态、终止原因和最后成功动作时间。

快照至少保存：

- 计划采样时间；
- 实际采样时间；
- 延迟毫秒数；
- 触发来源：开始、周期、结束前检查、最终结束或恢复；
- 原有网络、信号和流量状态。

## 失败与降级

- 标准模式中 Doze 导致迟到：照常采样并记录延迟。
- 严格模式运行中 VPN 被撤销、唤醒锁无法维持或采集器被终止：记录模式失效事件，立即尝试安全恢复；无法恢复时继续用标准短任务完成结算，但报告明确指出严格模式中断，不伪装为全程严格。
- 主动测速失败不得终止快照和连接采集。
- 任何服务异常都不能让数据库永久保留无法结算的 `RUNNING`。

## 验收

- 两种模式均不再连续运行六小时 `dataSync` 服务。
- 模拟 `onTimeout` 后服务及时停止，Run 可导出且原因明确。
- 计划开始前修改模式会作用于即将开始的 Run；运行中修改只影响下一次 Run。
- 严格模式缺少 VPN 授权时被阻止，并显示可操作的原因。
- 标准模式延迟快照和严格模式准时快照均在报告中显示计划时间、实际时间和延迟。
- K80 上完成短时间加速验收，并验证严格模式的 VPN、唤醒锁和最终结算；同一 APK 保持可供 K60 验收。
