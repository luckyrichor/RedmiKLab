# 增强型元数据诊断方案

## 目标

在不 Root、不解密 HTTPS、不保存数据包正文的前提下，完成以下能力：

- 修复 K60 在物理移动网络消失后仍把本地 VPN 绑定到失效底层网络的问题；
- 保持夜间诊断、严格采样、快照和主动测速调度彼此独立，避免一个子系统失效导致整次诊断停止；
- 把 Android 系统移动流量、VPN 观察流量、实际转发结果、测速和网络心跳分别统计；
- 实时采集媒体会话变化和相关 App 通知变化，并与前后台、锁屏、端点和流量关联；
- 对播放、缓存、疑似预加载、广告、统计上报和无法解释的后台上传给出有证据和置信度的分类；
- 同一 APK 继续兼容 Redmi K60 与 K80，保留旧数据库记录和旧 ZIP 导入兼容。

本方案是已确认的“方案二：增强型元数据诊断”。方案三所需的 HTTPS 解密、Root、插桩、请求正文及精确视频分片归属不在范围内。

## 用户可见行为

### 连接级采集

连接级采集继续由用户显式启用；标准模式可关闭，严格模式必须启用。它与 Clash Meta 等其他 Android VPN 互斥。

安排夜间诊断后，网络守护立即开始，不等待诊断窗口正式开始。诊断结束或计划被取消后，守护与本次计划一起结束。

### 标题与媒体信息

标题不是由 VPN 数据包直接读取。RedmiKLab 从 Android 向获授权应用公开的媒体会话和通知中读取：

```text
目标 App 内部媒体信息
  → 目标 App 选择写入媒体会话或通知
  → Android 系统保存公开字段
  → RedmiKLab 通过通知使用权读取
```

两个增强项必须同时实现：

1. 媒体会话不再只随状态快照定时读取。活动会话、播放状态或 metadata 发生变化时立即形成事件；标题短暂出现后又消失，也应保留出现时的记录。
2. 通知继续按发布、更新和移除事件实时记录，不等待状态快照。重复回调按通知 key、内容指纹和事件时间去重，但真正的内容变化不得被丢弃。

每 5 分钟状态快照仍读取一次当前媒体状态，作用是兜底、完整性检查和生成窗口汇总，不再是标题采集的唯一时机。

如果目标 App 从未把前台视频标题写入媒体会话或通知，RedmiKLab 必须显示“目标 App 未向 Android 提供”，不得把空字段误报为采集故障。本次不增加无障碍界面文字采集。

## 网络守护与恢复

### 状态机

网络生命周期至少包含：

```text
等待计划
→ 正常联网
→ 网络异常
→ 主动重连
→ 隧道暂停
→ 等待网络
→ 网络恢复
→ VPN 重建
→ 诊断结束
```

每次变化记录发生时间、旧状态、新状态、物理网络 ID、VPN 底层网络 ID、原因和重试轮次。

### 物理移动网络

候选网络必须是真实 `TRANSPORT_CELLULAR` 网络，并排除 VPN、IMS、EIMS、MMS 等专用网络。优先使用已验证网络；未验证但具备互联网能力的物理蜂窝网络可以作为待验证候选。

网络守护持续申请物理移动网络并监听网络对象变化。网络 ID、接口或能力变化时重新验证 VPN 底层绑定，不能仅因旧 `Network` 对象仍存在就认为可用。

### 心跳

使用极小流量心跳检测网络对象是否能够真正完成 DNS 和网络连接。心跳字节、结果、端点、耗时和失败阶段单独记录，不计入主动测速流量，也不能归到被观察 App。

### 有限重连

物理网络消失或心跳确认失效后，按以下节奏主动重连五次：

```text
立即 → 30 秒 → 1 分钟 → 2 分钟 → 5 分钟
```

五次均失败后，停止本轮密集重连，但继续被动监听。新物理网络随后出现时立即恢复并重建 VPN。

### 子系统隔离

没有物理网络时只暂停或拆除失效隧道，不销毁连接级采集前台服务、严格采样协调器或唤醒锁。此后：

- 状态快照仍按配置间隔执行；
- 主动测速仍按计划触发，但直接记录 `NO_PHYSICAL_CELLULAR_NETWORK`，不浪费主备端点的十次 URL 重试；
- 媒体和通知事件仍可记录本地 Android 状态；
- VPN 连接明细标记为采集盲区；
- 物理网络恢复后重建隧道并结束盲区。

## 状态快照

快照继续表示某个计划时刻附近的设备与网络状态，并附带自上一条快照结束后的连续、非重叠 Android 系统流量窗口。每条快照至少增加：

- 屏幕是否亮起、设备是否锁定；
- 是否充电；
- Android 深度空闲和轻度空闲状态；
- RedmiKLab 是否不受电池优化限制；
- 当前物理网络 ID、VPN 网络 ID、VPN 底层网络 ID；
- 网络守护状态、重连次数、最后丢失与恢复时间；
- 隧道是否有效、连接级采集是否完整、是否处于盲区；
- 当前前台 App 与当前媒体状态摘要。

快照、媒体事件和通知事件使用各自的时间戳。报告不得把媒体事件发生时间改写成最近快照时间。

## 流量分层

报告至少区分以下口径，并分别记录接收和发送方向：

1. **Android 系统移动流量**：`NetworkStatsManager` 的离散统计桶，按 UID/App 近似分摊。
2. **VPN 隧道观察字节**：App 交给 VPN 的上行和 VPN 返回给 App 的下行；可能包含最终未成功转发的请求。
3. **外部套接字接受的上行字节**：本地系统网络栈接受的写入量，不得命名为“服务器确认收到”。
4. **外部套接字收到的下行字节**：转发器从网络对端实际读取到的量。
5. **转发失败或丢弃字节**：按无物理网络、建连失败、写入失败、超时、DNS、UDP、隧道重建等原因分类。
6. **主动测速读取字节**：测速代码实际读取到的内容；失败尝试保留部分读取量，零读取不得按预留预算记为消耗。
7. **网络心跳流量**：网络守护产生的独立诊断流量。
8. **连接级采集盲区**：开始、结束、持续时间、原因，以及该时段系统统计到但没有连接明细的流量。
9. **未归属流量**：无法解析 UID 或包名的数据，不强行归属。
10. **统计差值**：说明不同采集层覆盖范围、时间边界和旁路流量造成的差异，不要求各层字节严格相等。

原生转发器需要在“观察到 TUN 数据包”和“外部套接字处理结果”两个位置分别回传计数，不能只用进入 TUN 的字节推断转发成功。

## 媒体、通知与端点关联

### 参与诊断的 App

满足任一条件的 App 参与完整关联：

- 连接级采集观察到网络连接；
- Android 系统移动流量出现非零变化；
- 诊断期间出现活动媒体会话；
- 诊断快照中被识别为前台 App。

只有前台背景、没有网络或媒体活动的 App 只保留包名、应用名和前台时间段；不导出其完整通知。

### 媒体事件

事件尽可能保存目标 App 向 Android 提供的：

- 包名、应用名、媒体会话标识；
- 事件来源：媒体回调、通知回调或快照兜底；
- 播放、暂停、缓冲、停止状态及变化时间；
- 播放位置、速度、时长；
- title、displayTitle、artist、album、mediaId；
- 媒体通知是否存在；
- 字段为空原因和权限完整性。

媒体回调和快照兜底产生相同状态时可以按内容指纹去重，但必须保留首次出现、最后出现和来源。

### 通知事件

对于网络参与 App 和媒体相关 App，保存 Android 实际提供的全部可序列化字段，包括 title、text、bigText、subText、summaryText、infoText、ticker、conversationTitle、messages、channel、category、group、tag、ongoing、MediaStyle 及发布时间、更新时间和移除时间。

诊断期间可以暂存通知，Run 结算后按参与 App 规则清理无关记录。普通推送标题只能证明通知存在，不能证明对应视频正在播放。

### 端点分类

可版本化规则库至少包含：

- `VIDEO_CDN`
- `AUDIO_CDN`
- `IMAGE`
- `API`
- `ADVERTISING`
- `ANALYTICS`
- `LOG_UPLOAD`
- `PUSH`
- `LIVE`
- `ECOMMERCE`
- `OTHER`
- `UNKNOWN`

分类保留规则版本、命中依据、域名来源和置信度。未知 IP 不强行分类；DNS、明文 SNI 或 DNS/IP 时间关联分别注明来源。

## 行为分类

分类器按时间窗口关联屏幕、锁屏、前台 App、媒体事件、通知、端点、上下行、突发模式和转发结果，输出：

- `LIKELY_FOREGROUND_PLAYBACK`
- `LIKELY_BACKGROUND_PLAYBACK`
- `LIKELY_CACHED_PLAYBACK`
- `POSSIBLE_PRELOAD`
- `POSSIBLE_ADVERTISING`
- `POSSIBLE_ANALYTICS`
- `POSSIBLE_LOG_UPLOAD`
- `UNEXPLAINED_BACKGROUND_UPLOAD`
- `UNCLASSIFIED`

每条结论包含时间范围、App、字节、证据列表、反证、置信等级和限制说明。

“疑似预加载”只能基于视频 CDN 突发、媒体状态与前后台关系作概率判断，不能宣称精确知道某个分片属于当前视频还是下一条视频。“无法解释的后台上传”不能写成“上传个人信息”，因为本方案看不到 HTTPS 正文。

## 数据存储与导出

数据库升级必须使用显式 Room migration，不破坏已有诊断记录。新增实体应按职责拆分网络生命周期、心跳、转发结果、采集盲区和媒体事件；高频事件需要批量写入、有界缓冲和幂等键，避免长时间诊断造成无界内存增长。

ZIP 至少新增或调整：

- `traffic_summary.csv`
- `system_mobile_traffic.csv`
- `tunnel_observed_traffic.csv`
- `forwarding_outcomes.csv`
- `probe_traffic.csv`
- `heartbeat_traffic.csv`
- `capture_gaps.csv`
- `network_lifecycle.csv`
- `endpoint_observations.csv`
- `media_events.csv`
- `notification_events.csv`
- `behavior_classifications.csv`
- `unexplained_uploads.csv`

HTML 增加数据完整性、网络丢失与恢复、流量口径对照、按 App 上下行、媒体时间线、疑似预加载/缓存/广告、后台上传排行、采集盲区和证据置信度。JSON schemaVersion 递增，旧 ZIP 继续可导入。

## 错误处理

- 通知使用权未授权或运行中撤销：诊断继续，报告记录权限缺失范围。
- 目标 App 字段为空：记录“目标 App 未提供”，不伪造标题。
- 媒体监听器重连：重新枚举当前会话并写入恢复事件，避免把恢复后的初始状态当成真实变化。
- 数据库写入失败：保留有界重试并记录丢失计数；不得让通知监听回调或 VPN 转发线程长期阻塞。
- 网络恢复与旧回调竞争：网络代次编号必须阻止旧网络回调重新绑定失效隧道。
- 服务重启：从持久化 Run ID、计划和网络状态恢复，不能创建不知道归属 Run 的新实例。

## 测试与验收

### 自动测试

- 网络守护状态机、五次重连、被动恢复和旧网络回调失效；
- 物理蜂窝候选排除 VPN、IMS、EIMS、MMS；
- 隧道暂停时严格采样、快照和测速调度继续；
- TUN 观察、上行接受、下行收到、丢弃、测速和心跳字节分别记账；
- 媒体 metadata 在两次快照之间短暂出现时，由事件回调保存；
- 通知发布、更新、移除实时保存，内容变化不被去重；
- 快照兜底与事件回调重复时只保留合理的首次/末次与来源；
- 行为分类的正例、反例和低置信回退；
- Room 旧版本升级、新旧 ZIP 导入和所有 CSV/HTML 文本转义。

### 真机验收

K60 与 K80 使用同一 APK，至少验证：

- 亮屏前台播放、锁屏后台播放、缓存播放和停止播放；
- 标题通知在快照间隔中出现后仍可导出；
- 无标题时报告明确为目标 App 未提供；
- 手动切换或短暂丢失物理移动网络后，旧隧道被暂停，新网络出现后自动重建；
- 其他 App 的视频、评论、点赞和消息接口不被失效 VPN 底层绑定破坏；
- 夜间深度休眠报告仍有严格快照，网络盲区、测速失败和恢复时间可解释。

完整验证命令为：

```bash
JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-17.jdk/Contents/Home \
ANDROID_HOME=/opt/homebrew/share/android-commandlinetools \
./gradlew test lintDebug assembleDebug
```

安装前必须先确认目标手机型号、Android 版本、当前数据库中没有 `RUNNING` 或 `FINALIZING` 诊断，再使用 `adb install -r` 保留数据安装。安装后检查启动、崩溃日志、数据库 migration、旧记录数量和关键服务状态。

## 明确边界

- 不使用 Root、Frida、Xposed、证书中间人或 HTTPS 解密；
- 不保存数据包负载、请求正文、账号凭证或视频二进制；
- 不承诺获得抖音普通前台短视频标题，除非抖音向 Android 媒体会话或通知提供；
- 不使用无障碍服务读取抖音页面文字；
- 不把本地套接字写入成功表述为服务器确认；
- 不把统计关联表述为逐包因果或个人信息上传事实；
- 不承诺 Android 厂商系统级硬实时，但严格模式继续用现有唤醒锁和绝对时刻调度提高准时率。
