# RedmiKLab：移动网络夜间诊断（第一期）设计

## 1. 目标与范围

RedmiKLab 是面向 Redmi K 系列设备的长期开发与测试代码库，当前覆盖 Redmi K60 和 K80。第一期交付一个免 Root 的 Android 应用，用于诊断两台手机在同一地点、使用中国电信移动数据时，夜间网络变慢的原因。

应用在用户指定的时间窗口内自动记录网络状态、主动网络探测和系统可取得的流量统计；默认窗口为 00:00–07:00，但所有时间与流量参数均可设置。应用应帮助区分：

- 运营商网络或当地覆盖在同一时段整体变慢；
- 单机信号、网络制式回落或网络频繁切换；
- 有迹象表明后台应用流量与网速下降同时出现。

本期不包含本地 VPN 抓包、Root、ADB 常驻采集、云端上传或电脑端原生应用。

## 2. 约束与边界

- 两部手机同地，均使用中国电信移动数据；同一 APK 安装于两机。
- 用户可安装测试应用，授予使用情况访问、通知和电话状态等必要权限，并允许夜间前台服务、自启动及不受电池优化限制。
- 数据默认只保留在手机本地。可导出 ZIP 到电脑，其中包含离线 HTML 报告、CSV 和 JSON。
- Android 的普通应用流量统计是时段级系统统计，不是逐包记录。报告只能将应用流量与网络变慢做时段关联，不能声称单个应用在某分钟占满带宽。
- Android 通常仅允许一个活动 VPN。Clash Meta 运行时不启用未来可选的本地 VPN 深度诊断模式。

## 3. 技术路线

采用标准 Android App + 系统 API 的方案。其低风险、免 Root，且适合长期扩展。未来新增本地 VPN 或 ADB 数据源时，须转换为既定数据模型，不改变报告和导出逻辑。

不采用首期本地 VPN：它会与 Clash Meta 冲突，且会增加耗电、兼容性、隐私和实现复杂度。

不采用首期 ADB：夜间持续连接电脑不实用，且不符合独立手机诊断的目标。

## 4. 模块结构

```text
app                 应用启动、界面与依赖装配
core:model          稳定数据模型和公共接口
core:storage        Room/SQLite、本地查询和导出
feature:diagnostics 夜间编排、网络快照、流量采集、主动探测
feature:reports     摘要、双机对比、HTML/CSV/JSON 报告
```

关键边界：

- `NetworkSnapshotSource`：提供网络制式、信号、连接和切换信息。
- `TrafficStatsSource`：提供设备级和系统允许范围内的应用级移动数据统计。
- `ProbeRunner`：执行 DNS、HTTPS 延迟和受预算限制的吞吐探测。
- `DiagnosticRunCoordinator`：根据配置启动、维持、停止一晚的诊断运行。
- `ReportGenerator`：只消费标准化记录，生成单机报告与导出包。

## 5. 配置、采集与数据流

用户可设置开始/结束时间（支持跨午夜）、状态采样间隔、连通性探测间隔、吞吐测速间隔、单次测速流量上限和单夜总流量预算。

默认值：00:00–07:00；状态快照 5 分钟；DNS/HTTPS 探测 10 分钟；吞吐测速 30 分钟；每次吞吐测速最多 5 MB；一晚最多 100 MB。

每条网络快照包含时间、移动数据连接状态、网络制式、运营商、漫游状态、可取得的信号指标与网络切换事件。探测记录包含 DNS 耗时、HTTPS 连通性与延迟、下载/上传吞吐及消耗字节数。流量记录包含设备总移动流量与可取得的按应用统计、Top 应用列表和统计时间窗口。

开始时间触发后，应用启动带通知的前台服务；服务按配置循环采集并写入 Room 数据库。结束时服务停止，生成摘要。两机独立运行和保存；导出任一手机报告后，可在另一台手机导入对方 ZIP 生成同地同期的对比报告。

## 6. 结论规则

- 两机同期吞吐同步下降，且信号和网络制式相近：倾向电信网络侧拥塞、维护或当地覆盖问题。
- 仅一机下降，同时信号差、5G 回落到 4G 或切换频繁：倾向该机无线接入问题。
- 设备移动流量突增，且某些应用在相邻系统统计时段显著增加：提示后台流量可能参与影响。
- 信号正常且无显著后台流量，但 DNS、HTTPS 与吞吐同时下降：提示网络路径或运营商侧问题。

每项结论必须展示其证据和置信度，不将关联关系表述为因果关系。

## 7. 报告与电脑查看

应用内报告显示时序曲线、测速、网络制式和信号变化、流量异常、证据和解释建议。每晚可导出 ZIP：

- `report.html`：可离线在电脑浏览器打开的可视化报告；
- `snapshots.csv`、`probes.csv`、`traffic.csv`：供 Excel、Numbers 等工具分析；
- `report.json`：供后续电脑端工具或自动化处理。

用户可经 USB、局域网共享或其他传输方式将 ZIP 拷贝至电脑。后续可在 RedmiKLab 中新增电脑端双机分析工具。

## 8. 可靠性与错误处理

应用启动时检查权限与设备设置；对缺失的通知、使用情况访问、电话状态、自启动或电池优化豁免给出操作指引。权限撤销、系统终止、预算耗尽、网络探测失败、设备重启和计划任务未能启动都必须记录为可见事件。

一次探测失败不终止整晚任务。失败使用有限次数的指数退避重试，并保留缺失区间。预算耗尽时停止主动吞吐测试，但继续低成本状态采集。结束时间到达后自动关闭前台服务并生成摘要。

## 9. 验证策略

- 单元测试：配置校验、预算计算、结论规则、报告数据转换。
- 集成测试：模拟断网、低吞吐、权限拒绝、预算耗尽、应用流量异常和重试。
- 真机验收：K60 与 K80 各进行至少一整晚运行，覆盖锁屏、重启、前台服务保活、双机导出和电脑端离线报告查看。

## 10. 后续扩展

后续模块可以包括：关闭 Clash 时可选的本地 VPN 深度归因、按需 ADB 采集器、电脑端双机对比工具，以及独立的 Android App、脚本和测试工具。新增能力必须使用独立 feature 模块和稳定公共接口，避免改变现有诊断报告的数据契约。
