# 方案 A 真机高保真修正

## 问题证据

2026-07-23 在 Redmi K80（1080×2400、450 dpi、字体缩放 1.0）截取真机画面后，
确认上一轮实现只移植了颜色角色和分组，未完整移植浏览器方案 A 的控件结构。

- 主操作仍使用系统 `Button`，MIUI 注入了阴影、字体留白和较大的默认尺寸。
- 普通操作误用卡片描边 `#E3E8EF`，而原型按钮描边是更清晰的 `#CFD8E5`。
- 设置行缺少原型中的右箭头、开关和状态徽标。
- 设置窗口仍由系统 `AlertDialog` 排版标题、说明、滚轮和操作区，尺寸远大于原型。
- 自动化测试只检查了颜色常量和标签，没有验证真实尺寸、系统控件残留与真机截图。

## 唯一视觉依据

继续以已确认的浏览器方案 A 为依据，不重新设计：

- 页面：`#F6F8FB` / Android 页面承载层 `#EDF2F7`
- 卡片：白色、`#E4E9F0` 细描边、14dp 圆角、极弱阴影
- 卡片强调条：3dp × 20dp；参数蓝、模式紫、权限橙、运行绿、报告灰
- 普通按钮：白底、`#CFD8E5` 1dp 描边、9dp 圆角、无系统阴影
- 停止按钮：白底、`#E6C5C5` 描边、`#A33D3D` 文字
- 主按钮：`#2864DC` 实心；计划按钮：`#E9F0FC` 淡蓝
- 设置行文字约 12sp，板块标题约 13sp，操作按钮约 12sp
- 操作按钮可视高度 36dp，不使用系统 Button 的默认最小高度、背景 tint 或 elevation

## 主页面组件

### 顶部

保留目前已有的项目名称、诊断说明、窗口摘要和模式状态，不删除业务信息。
只收紧字号、行距和上下留白，使其接近方案 A 的紧凑 AppBar。

### 设置行

- 参数行：右侧显示灰蓝值和 `›`。
- “严格模式”“连接级采集”“精确夜间采样闹钟”：显示可点击的胶囊开关，不再用大号蓝色文字表示。
- 权限行：用小型状态徽标显示“去授权”“可选”“去管理”，末尾显示 `›`。
- 问号图标改用原型的灰蓝细描边，不使用高饱和蓝色大圆圈。

### 操作按钮

全部改为项目自绘的可点击文本控件，不再实例化系统 `Button`。保留原点击回调、
无障碍焦点和按压反馈，不改变诊断、计划、导入导出业务逻辑。

## 设置窗口

系统对话框只作为透明窗口容器；标题、说明、字段、滚轮和按钮全部由项目自绘。

- 面板白底、`#DCE3EC` 描边、17dp 圆角。
- 标题 15sp，说明 11sp，字段 11–12sp。
- 输入框使用 `#BAC6D5` 描边和 10dp 圆角。
- 取消与保存使用同一套 36dp 扁平按钮。
- 快照与时间滚轮限制为紧凑高度；选中行使用淡蓝背景。
- 时间窗口继续同时支持滚轮和手动输入，保留 24 小时制与最长 6 小时说明。
- 输出格式只显示 `.zip`、`.json`、`.html`、`.pdf`。

## 二级页面

历史诊断导出、导入、比较和分析继续使用相同卡片与扁平按钮组件。不得出现
系统 Button 阴影、系统默认下拉行或与主页面不同的按钮描边。

## 验收

1. 自动化测试验证按钮实际类型、36dp 高度、无 elevation、专用按钮描边常量、
   设置行箭头/开关/徽标以及自绘对话框结构。
2. `./gradlew test lintDebug assembleDebug` 全部通过。
3. 安装前确认无 `RUNNING`/`FINALIZING` 诊断。
4. 安装后在真机截取：
   - 主页面参数/模式/权限区域；
   - 立即运行/夜间计划/报告按钮区域；
   - 至少一个设置窗口。
5. 三张真机图逐项对照浏览器方案 A；若仍出现系统按钮阴影、边框缺失或原生大弹窗，
   不得宣称完成。
