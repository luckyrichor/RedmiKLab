# 锁屏定时可靠性、最终快照与安全滚动设计

## 根因

Android Doze 对同一应用的 `setExactAndAllowWhileIdle` 触发频率有限制，不能把它作为每五分钟持续采样的唯一机制。K80 本次报告显示延迟的快照事件和结束事件同时送达；旧代码让过期快照直接停止服务，与结束事件的最终快照竞争。

## 方案

- 已启动的前台服务使用持有的部分唤醒锁和进程内 `Handler` 安排五分钟快照与结束时刻，避免把每次周期采样交给受 Doze 频率限制的闹钟。
- 仅保留精确闹钟作为结束事件的兜底；若它迟到，或有迟到快照事件到达，二者均进入同一个最终化入口。
- `FinalSnapshotGate` 保证只执行一次最终快照，数据库写入完成后才停止服务。
- 设置页提供 Android 系统的直接电池优化豁免请求；用户必须亲自确认。此授权与前台服务、部分唤醒锁共同减少小米系统锁屏限制，但普通应用无法承诺绕过用户强行停止或厂商极端限制。
- 滚动区按系统导航栏底部 inset 增加内边距，末项不再被三键导航栏遮挡；删除临时占位按钮。
