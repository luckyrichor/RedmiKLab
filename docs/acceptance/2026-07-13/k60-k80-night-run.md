# K60 / K80 移动网络诊断与连接级采集验收

## 安装

将同一提交构建出的 `app-debug.apk` 安装到 K60 与 K80。两机均关闭 Wi-Fi、开启中国电信移动数据，并放在同一地点。记录 ADB 显示的型号、Android 版本、移动网络接口及 IPv4/IPv6 地址。

当前待安装到 K60 的候选包来自提交 `96ae500`，路径为 `app/build/outputs/apk/debug/app-debug.apk`，大小 3,044,582 字节，SHA-256 为 `c3f79db7a87f325465dd48c2079a6ff4e6ca873475f0a4bf204139947eaed4a0`。安装前重新计算哈希；若不同，必须重跑全量检查并更新本记录，不能把不同构建误当成双机同版验收。

## 首次授权

在两机上分别：

1. 允许通知与电话状态权限。
2. 在系统设置中授予“使用情况访问”。
3. 将 RedmiKLab 设置为无限制电池策略并允许自启动。
4. 对 Xiaomi/HyperOS 的后台管理，允许应用在后台运行。
5. 如需连接级采集，关闭 Clash Meta 的 VPN 模式，点击“连接级采集：已关闭（点击开启）”，并确认 Android 本地 VPN 授权。

## 运行

1. 在 App 设置开始时间，例如 00:00。
2. 设置结束时间，例如 06:00；诊断窗口最长为 6 小时，满 6 小时时会在结束前 120 秒开始安全收尾。如需短测，设置为当前时间后 10 分钟。
3. 点击“按窗口计划夜间诊断”。
4. 在测试窗口前确认通知权限已授予；窗口到达时应出现“RedmiKLab 夜间诊断运行中”通知。
5. 也可点击“开始诊断”立即进行短测；到设置的结束时间会自动停止，也可手动停止。

## 每台手机的验收矩阵

1. 连接级采集关闭时，移动数据可以正常联网，诊断仍可生成系统 UID 近似流量统计。
2. 连接级采集开启时，系统出现 RedmiKLab VPN，`tun0` 同时存在 IPv4/IPv6 地址，浏览器可经中国电信移动数据打开国内网站。
3. 亮屏前台使用浏览器或视频 App，报告出现 `FOREGROUND_ACTIVE`；亮屏但应用不在前台时出现 `BACKGROUND_SCREEN_ON`。
4. 锁屏后继续后台播放或保留后台网络活动，诊断通知和连接级采集通知仍存在，报告出现 `BACKGROUND_SCREEN_LOCKED`。
5. 主动测速应选择具备 Internet、非受限且已验证的蜂窝数据网络；记录主/备用端点的每一次尝试、DNS、HTTPS、字节数和失败类别。
6. 点击“停止当前诊断”后，夜间诊断服务消失，最近 Run 变为 `COMPLETED` 或可解释的 `INTERRUPTED`，数据库不得遗留 `RUNNING`；连接级采集可继续独立运行。
7. 点击“导出最近一次报告到文件”生成 ZIP。ZIP 至少包含 `report.html`、`snapshots.csv`、`probes.csv`、`probe_attempts.csv`、`traffic.csv`、`connection_flows.csv` 和 `report.json`。
8. 将 ZIP 拷贝到电脑并解压；浏览器可离线打开 `report.html`，Excel/Numbers 可打开 CSV。
9. 将其中一台的 ZIP 传到另一台，在后者点击“导入另一台手机的报告并比较”；显示的吞吐和快照比较仅是关联线索，不视为因果证明。
